# MBT Crate Short Names Spec

## 1. Identification

Spec slug: `mbt_crate_short_names`

Research brief:
`docs/reviews/mbt_crate_short_names/mbt_crate_short_names_research_brief.md`

Target repository:
`/home/tia/_DEV/MATHILDE/metamorphic-binary-transport`

## 2. Status

Status: draft for peer audit.

This spec is not approved for implementation until a separate peer audit passes
and an implementation plan is written and approved.

## 3. Purpose

Shorten the Rust crate/package/import surface from
`metamorphic_binary_transport_*` to `mbt_*`.

The purpose is ergonomic:

- shorter `Cargo.toml` dependency names;
- shorter Rust imports in applications and SDKs;
- shorter generated imports emitted by `mbt_codegen`;
- no behavioral change to MBT bytes, validation, projections, metamorphose,
  transponding, compression, benches, or adapters.

## 4. Non-goals

- Do not rename repository directories.
- Do not rename the repository.
- Do not change the `mbt_codegen` binary name.
- Do not change the MBT wire format.
- Do not change schema hashes.
- Do not change envelope validation.
- Do not change checked or trusted access semantics.
- Do not change projection algorithms.
- Do not change metamorphose algorithms.
- Do not change transponding algorithms.
- Do not change compression algorithms.
- Do not rewrite historical evidence artifacts.
- Do not add dependencies.
- Do not create a `crates/projection` crate.

## 5. Measured object

The measured object is the crate/package/import naming surface.

Correctness means every current source, manifest, generated artifact, README
example, architecture reference, inventory reference, and active command surface
uses the new `mbt_*` crate names.

No runtime speed claim is made by this spec.

- proto packages;
- root messages;
- field options;
- projection definitions;
- dictionary definitions;
- derived UTC definitions;
- schema hashes.

## 7. Wire and archive contract

Wire and archive bytes are unchanged.

The rename must not alter:

- `HEADER_LEN`;
- schema ID;
- schema version;
- schema hash;
- normalized proto hash;
- payload checksum;
- archive struct layout;
- presence bitmap semantics;
- row ordering.

## 8. Checked and trusted access contract

Checked access remains:

```text
MBT bytes -> header validation -> archive validation -> view
```

Trusted access remains:

```text
previously validated immutable MBT bytes -> trusted payload access -> view
```

The rename must not change safe/unsafe API distinctions or safety text.

## 11. Dependency contract

Every dependency key that currently uses `metamorphic_binary_transport_*` must
use the matching `mbt_*` name.

Schema crate feature `dep:` entries must also use the short names.

No new dependency is allowed.

No dependency version may change.

`Cargo.lock` is a local ignored Cargo artifact in this repository. Cargo may
update it during validation, but it is not a tracked output of this spec unless
repository policy changes.

The `mbt_codegen` binary name remains:

```toml
[[bin]]
name = "mbt_codegen"
```

## 12. Determinism contract

Codegen output must remain deterministic.

Running the same codegen command twice after the rename must produce identical
generated files.

The rename must not change deterministic checksums for encoded logical rows.

## 13. Failure contract

Failure behavior is unchanged.

Implementation must fail validation if:

- any current source import still uses `metamorphic_binary_transport_*`;
- any current manifest package or dependency key still uses
  `metamorphic_binary_transport_*`;
- codegen emits a long crate name;
- generated schema files require manual edits;
- README examples use long package/import names;
- `cargo check` cannot resolve the renamed crates;
- feature-gated adapter builds fail.

Historical review, old spec, and evidence artifacts are not part of this
failure surface unless an approved implementation plan binds a targeted
historical-doc rewrite.

## 14. Compile-surface budget

This is a naming-only change. The allowed compile-surface impact is:

- no new crates;
- no removed crates;
- no new dependencies;
- no new adapter surfaces;
- generated source line count may change only by import name length and
  formatting changes caused by rustfmt.

Compile evidence must run after implementation:

```bash
/usr/bin/time -f 'elapsed=%e user=%U sys=%S max_rss_kb=%M' cargo check -p mbt_core
/usr/bin/time -f 'elapsed=%e user=%U sys=%S max_rss_kb=%M' cargo check -p mbt_codegen --all-targets

```

## 15. Runtime performance budget

No runtime performance change is expected or claimed.

No benchmark is required to prove this naming change. Existing runtime
benchmark evidence remains valid only for the implementation that produced it.

If a benchmark is run after this rename, it must be reported as a post-rename
sanity check, not as proof of a new speed claim.

## 16. Correctness oracle

Correctness is proved by:

1. `cargo check` resolving all renamed crates;
2. tests passing for core, codegen, schemas, adapters, compression, and benches;
3. codegen `--check` passing for regenerated schema modules;
4. grep proving no long crate names remain in current source, manifests,
   README, architecture, and inventories;
5. deterministic generated-code check passing by regenerating through codegen.

## 17. Benchmark methodology

No performance benchmark is required.

Build checks are required because package names affect compile resolution and
generated source.

If optional benchmark smoke is requested later, it must run only after all
correctness and codegen checks pass.
