## Findings

### 1. Inventory is bound as an updated artifact, but the generation command is missing

Severity: blocking

Evidence:

- `docs/specs/mbt_crate_short_names_SPEC.md` binds inventory updates under
  code bindings:

```text
inventory.md
crates/*/docs/inventory.md
crates/adapters/*/docs/inventory.md
crates/schemas/*/docs/inventory.md
```

- `Makefile.toml` defines the inventory command:

```text
cargo make inventory
```

- `bin/generate_global_inventory.rs` is the generator used by that command.

Problem:

The spec requires inventory updates but does not bind `cargo make inventory` in
the test plan, generated/current artifact contract, or validation command list.
This violates the pre-audit closure gate requiring every command surface to be
exact.

Required correction:

Add an inventory artifact contract that states:

- `inventory.md` is generated by `cargo make inventory`;
- per-component `docs/inventory.md` files are manually maintained current
  source inventories unless a later generator owns them;
- validation must run `cargo make inventory`;
- the static long-name grep runs after inventory generation.

### 2. Codegen smoke-crate dependency emission is not explicitly bound in the codegen contract

Severity: blocking

Evidence:

- `crates/codegen/src/emit.rs` emits a temporary smoke `Cargo.toml` containing:

```toml
metamorphic_binary_transport_core = { path = ... }
```

- `docs/specs/mbt_crate_short_names_SPEC.md` code bindings include
  `crates/codegen/src/emit.rs`.

- The codegen contract section lists `crates/codegen/src/rust_emit.rs` emitted
  imports but not the smoke manifest emitted by `crates/codegen/src/emit.rs`.

Problem:

The smoke crate is a generated codegen validation surface. If this is not
explicitly bound, implementation can update generated schema imports but leave
the codegen smoke check producing a long package name.

Required correction:

Add to the codegen contract:

```text
crates/codegen/src/emit.rs smoke manifest dependency:
metamorphic_binary_transport_core -> mbt_core
```

Also bind a validation check that `crates/codegen/src/emit.rs` no longer
contains `metamorphic_binary_transport_*`.

### 3. Static grep commands should explicitly exclude target directories

Severity: blocking

Evidence:

- The spec static check searches `crates`:

```bash
! rg -n "metamorphic_binary_transport_[a-z0-9_]+" Cargo.toml crates README.md architecture.md inventory.md docs/architecture/repository_structure.md --glob '!docs/reviews/**' --glob '!docs/specs/**' --glob '!docs/evidence/**'
```

- A codegen target directory exists under:

```text
crates/codegen/target/
```

Problem:

The static grep relies on ignore behavior for target directories. That is not
an explicit command contract. Generated temp target content can create false
failures or hide stale generated smoke content depending on ignore settings.

Required correction:

Make the static grep command explicit:

```bash
! rg -n "metamorphic_binary_transport_[a-z0-9_]+" Cargo.toml crates README.md architecture.md inventory.md docs/architecture/repository_structure.md --glob '!target/**' --glob '!crates/**/target/**' --glob '!docs/reviews/**' --glob '!docs/specs/**' --glob '!docs/evidence/**'
```

Apply the same target exclusions to the manifest grep command if it searches
under `crates`.

### 4. `Cargo.lock` status is unbound

Severity: non-blocking if explicitly documented; blocking if ignored in the
amended spec

Evidence:

- Local command showed:

```text
!! Cargo.lock
```

This means the local `Cargo.lock` is ignored.

Problem:

Renaming packages can update `Cargo.lock`. Because the file is ignored in this
repository, implementation should not treat it as a tracked artifact. The spec
does not state this.

Required correction:

Add a short dependency artifact note:

- `Cargo.lock` is a local ignored Cargo artifact in this repository;
- it may be updated locally by Cargo during validation;
- it is not a tracked output of this spec unless repository policy changes.

## Passing Checks

- The mandatory spec section order matches `spec_protocol.md`.
- The measured object is narrow: package/import naming only.
- The spec preserves wire/archive/runtime behavior.
- The package rename table is complete for current workspace crates.
- Historical evidence/reviews are excluded from rewrite scope, which preserves
  prior run records.
- Generated schema files are correctly treated as codegen-owned and not
  hand-edited.
- The spec correctly supersedes only the package-name table from
  `mbt_workspace_architecture_SPEC.md`.

## Required Amendments

Before the next audit, amend
`docs/specs/mbt_crate_short_names_SPEC.md` to include:

1. inventory generation command and artifact ownership;
2. explicit `crates/codegen/src/emit.rs` smoke manifest rename;
3. explicit target-directory exclusions in grep checks;
4. `Cargo.lock` ignored-artifact policy.

## Exit

The spec is not implementation-ready.
