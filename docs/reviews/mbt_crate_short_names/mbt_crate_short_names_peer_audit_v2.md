## Prior Blocker Resolution

### 1. Inventory command and ownership

Status: resolved.

Evidence:

- The spec now binds `cargo make inventory` under required checks.
- The spec now states that root `inventory.md` is generated by
  `cargo make inventory`.
- The spec now states that per-component inventories are manually maintained
  unless a later generator owns them.
- The spec now requires static long-name grep checks after inventory
  generation.

### 2. Codegen smoke manifest rename

Status: resolved.

Evidence:

- The spec now binds `crates/codegen/src/emit.rs` smoke manifest dependency
  rename:

```text
metamorphic_binary_transport_core -> mbt_core
```

- The static codegen grep now includes `crates/codegen/src/emit.rs`.

### 3. Explicit target exclusions

Status: resolved.

Evidence:

- Static grep commands now include:

```text
--glob '!target/**'
--glob '!crates/**/target/**'
```

### 4. Cargo.lock policy

Status: resolved.

Evidence:

- The dependency contract now states that `Cargo.lock` is a local ignored Cargo
  artifact and not a tracked output of the spec unless repository policy
  changes.

## Audit Checks

### Pre-audit closure gate

Status: passed.

The spec explicitly covers:

- mandatory section order;
- prior workspace package-name conflict and local supersession;
- exact cargo command surfaces for codegen, tests, cargo tree, inventory, and
  grep checks;
- generated artifact ownership by `mbt_codegen`;
- source, manifest, generated, documentation, and inventory bindings;
- codegen dispatch paths in `rust_emit.rs` and `emit.rs`;
- tests and docs that encode old package names;
- compile-surface evidence commands.

### Scope control

Status: passed.

The measured object is package/import naming only. The spec preserves:

- wire/archive behavior;
- checked and trusted access;
- projections;
- metamorphose;
- transponding;
- compression;
- dependency versions;
- crate paths;
- repository name.

### Codegen ownership

Status: passed.

The spec requires generated schema modules to be regenerated through
`mbt_codegen`, not hand edited. Both Bars and test-compatibility generated
artifacts have explicit write commands and require matching `--check`
commands.

### Crate boundary isolation

Status: passed.

The rename table covers every current workspace package observed in source,
including compression and schema crates. The spec does not recreate
`crates/projection`.

### Failure contract

Status: passed.

The failure contract rejects partial rename states, unresolved cargo packages,
long codegen output names, manual generated edits, stale README examples, and
feature-gated adapter build failures.

### Test and validation binding

Status: passed.

The spec binds:

- `cargo fmt --check`;
- tests for core, codegen, metamorphose, transponding, compression, adapters,
  schema crates, and benches;
- compile timing checks;
- dependency tree checks;
- inventory generation;
- static long-name grep checks with target exclusions.

## Residual Risks

- Implementation remains mechanically broad. The implementation plan must bind
  the exact edit order so codegen is changed before generated files are
  regenerated.
- Historical docs and evidence will still contain long names by design. The
  implementation report must state that this is preserved history, not current
  API surface.
- `Cargo.lock` may change locally during validation but is ignored. The result
  review must not report it as a tracked artifact.

## Required Implementation Plan Constraints

The implementation plan must:

1. rename Cargo packages and dependency keys first;
2. update non-generated source imports;
3. update `crates/codegen/src/emit.rs` and `crates/codegen/src/rust_emit.rs`;
4. regenerate schema artifacts with the exact spec commands;
5. update current README, architecture, and inventory surfaces;
6. run `cargo make inventory`;
7. run all validation commands from the spec;
8. record any skipped command as a blocker, not a pass.

## Exit

The spec is ready for implementation planning.
