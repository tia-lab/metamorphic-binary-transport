## V3 Blocker Closure

### 1. Adapter And Metamorphose Ownership

Result: passed.

Evidence:

- Section 10 states `crates/metamorphose` owns only public boundary conversion
  traits/enums and shared checked-output helpers.
- Section 10 states concrete JSON, protobuf, CSV, Arrow, Arrow IPC, and
  Parquet writers are not owned by `crates/metamorphose`.
- Section 17 requires:

```text
test ! -e crates/metamorphose/src/json.rs
test ! -e crates/metamorphose/src/protobuf.rs
test ! -e crates/metamorphose/src/csv.rs
```

The duplicate writer surface identified in v3 is removed.

### 2. Protobuf Options Ownership

Result: passed.

Evidence:

- Section 6 binds the MBT option ownership path:

```text
proto/mathilde/options.proto
```

- Section 10 binds exact placeholder source text for that file.
- Section 17 requires:

```text
test -e proto/mathilde/options.proto
```

The spec now owns the options path without implementing full extension
definitions in this skeleton phase.

### 3. Exact Skeleton Source And Manifest Contents

Result: passed.

Evidence:

- Section 10 binds exact root `Cargo.toml` content.
- Section 10 binds exact manifest template and package-name table for every
  skeleton crate.
- Section 10 binds exact source text for:
  - `proto/mathilde/options.proto`;
  - core modules;
  - codegen modules;
  - projection modules;
  - metamorphose modules;
  - transponding modules;
  - adapter `lib.rs` templates;
  - benches `lib.rs`;
  - every `src/tests/mod.rs`.

The implementation plan no longer has discretion to invent skeleton source
shape.

### 4. Generated Output Surface Separation

Result: passed.

Evidence:

- Section 18 now states generated-output import checks are deferred to later
  codegen specs because generated output is forbidden in this skeleton phase.
- Section 20 reserves generated output surfaces for later specs and forbids
  generated artifacts in this phase.

The skeleton correctness oracle is now separated from future codegen
contracts.

### 5. Stale Verbose Paths, Lockfile, And Build Output

Result: passed.

Evidence:

- Section 19 requires removing rejected verbose paths if they exist:

```text
crates/metamorphic_binary_transport_core
crates/metamorphic_binary_transport_codegen
crates/metamorphic_binary_transport_benches
```

- Section 22 states `Cargo.lock` is Cargo-generated, may be deleted before
  validation, and final lockfile must be generated by
  `cargo check --workspace`.
- Section 22 states `target/` is build output and not source cleanup.

The cleanup authority is now explicit enough for implementation planning.

## Additional Audit Checks

### Mandatory Spec Sections

Result: passed.

The amended spec uses the mandatory section order from
`docs/protocols/spec_protocol.md`.

### Compile-Surface Isolation

Result: passed.

The spec binds no dependencies in skeleton crates and requires per-crate
`cargo check` and `cargo tree` checks.

### Runtime And Adapter Non-Implementation

Result: passed.

The spec forbids runtime logic, codegen logic, adapter logic, generated
artifacts, and benchmark logic in this phase.

### Downstream Runtime Spec Safety

Result: passed.

The workspace architecture spec identifies stale downstream bindings, and
`docs/specs/mbt_core_runtime_migration_SPEC.md` is already blocked by the
workspace architecture amendment.

## Remaining Implementation-Plan Requirements

The next implementation plan must bind:

- removal of the rejected verbose crate folders;
- deletion of root `src/main.rs` if present;
- creation of the exact canonical tree;
- exact source text from section 10;
- `Cargo.lock` regeneration behavior;
- validation commands and expected output;
- dependency tree checks;
- `cargo metadata` check proving the exact workspace member set;
- rollback boundary.

These are implementation-plan requirements, not remaining spec blockers.

## Final Classification

`PEER_AUDIT_PASSED`

The spec is ready for an amended implementation plan for the corrected
workspace skeleton only. It does not authorize core runtime migration, codegen
implementation, schema generation, adapter implementation, benchmark fixtures,
benchmark execution, or generated artifacts.
