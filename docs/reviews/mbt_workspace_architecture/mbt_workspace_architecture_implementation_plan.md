## 1. Goal

Implement only the approved corrected workspace skeleton for the new
Metamorphic Binary Transport repository.

The implementation converts the root crate into a virtual Cargo workspace,
removes the rejected verbose crate folders, and creates the canonical short
folder structure:

```text
crates/core
crates/codegen
crates/projection
crates/metamorphose
crates/transponding
crates/adapters/json
crates/adapters/protobuf
crates/adapters/csv
crates/adapters/arrow
crates/adapters/arrow_ipc
crates/adapters/parquet
crates/benches
```

This plan does not authorize runtime migration, codegen implementation,
generated schemas, adapter implementation, benchmark fixtures, or performance
claims.

## 3. Implementation Scope

Allowed:

- replace root `Cargo.toml` with the exact virtual-workspace manifest in this
  plan;
- delete root `src/main.rs` if present;
- remove root `src/` if it becomes empty;
- remove rejected verbose crate folders if present;
- create `proto/mathilde/options.proto`;
- create exactly the canonical short crate folders and files listed in this
  plan;
- delete stale `Cargo.lock` before validation if needed;
- let Cargo regenerate the final `Cargo.lock` by running
  `cargo check --workspace`.

Forbidden:

- runtime envelope implementation;
- runtime trait implementation;
- rkyv archive access implementation;
- checked access implementation;
- trusted access implementation;
- checksum implementation;
- codegen descriptor parsing;
- codegen file generation;
- full protobuf option extension definitions;
- generated schema artifacts;
- generated protobuf DTOs;
- concrete JSON adapter logic;
- concrete protobuf adapter logic;
- concrete CSV adapter logic;
- concrete Arrow adapter logic;
- concrete Arrow IPC adapter logic;
- concrete Parquet adapter logic;
- schema crates;
- benchmark fixtures;
- benchmark dependencies;
- manually editing `Cargo.lock`;
- treating `target/` as source state;
- performance or compile-time claims beyond successful structural validation.

## 14. Rollback Boundary

Rollback for this phase is limited to:

- restore the previous root `Cargo.toml`;
- restore `src/main.rs` if it existed before implementation;
- remove the canonical short crate directories created by this plan;
- remove `proto/mathilde/options.proto`;
- restore the rejected verbose crate folders only if the implementation fails
  and the user explicitly asks to return to the pre-plan state.

No runtime or generated code exists in this phase, so rollback must not touch
runtime logic, schemas, adapters, or benchmark artifacts.

## 15. Known Risks

Risk: the skeleton compiles but proves only workspace structure.

Mitigation: the result review must state that no runtime behavior,
performance, codegen behavior, or adapter behavior is proved by this phase.

Risk: future implementation could migrate too much into core.

Mitigation: later specs must preserve the dependency checks introduced here and
must measure compile surface when generated code or adapters are added.

Risk: `Cargo.lock` may retain stale entries if the workspace is not regenerated
by Cargo.

Mitigation: validation requires a final `Cargo.lock` generated by
`cargo check --workspace`.
