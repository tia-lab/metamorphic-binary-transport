# MBT Projection Direct Writer Research Brief

Status: draft
Slug: `mbt_projection_direct_writer`
Task class: research and corrective spec preparation

This brief does not authorize code changes.

## Goal

Correct the migrated projection implementation so projected MBT output is
generated by schema-specific code without materializing owned projected rows.
The target is same-or-better performance than the old
`mathilde-binary-transport` projection benchmark lanes.

## Measured Object

The measured object is MBT-to-MBT projection:

```text
source MBT bytes
  -> checked or trusted archived source payload
  -> generated schema-specific projection writer
  -> projected MBT bytes
```

Projection is not JSON, protobuf, CSV, Arrow, Parquet, or a generic runtime
filter.

## Current New Crate Evidence

Code-read evidence from this repository:

- `crates/codegen/src/rust_emit.rs` emits projection functions from
  `emit_source_projection_api`.
- The generated projection body creates `Vec::with_capacity(...)`,
  pushes projected owned rows, and calls `ProjectionMarker::encode_owned`.
- The generated compatibility schema also emits `.to_string()`, `.to_vec()`,
  and `.collect()` for raw strings, bytes, and arrays in the projection hot
  path.

Conclusion from evidence: current projection is generated and MBT-to-MBT, but
it is not the accepted production hot path.

## Candidate Approach

Generate a schema-specific borrowed projection serializer:

```text
ArchivedSourcePayload
  -> ProjectedPayloadRef<'a>
  -> ProjectedRowRef<'a> iterator
  -> rkyv serialization directly to projected payload bytes
  -> MBT envelope for projected schema
```

The generated borrowed projection layer must:

- be emitted only for `--surface projection`;
- live in the generated schema module, not in a generic runtime engine;
- use `ArchivedVec::serialize_from_iter` to serialize projected row references
  directly;
- avoid constructing `Vec<ProjectedRow>`;
- avoid `.to_string()`, `.to_vec()`, and `.collect()` in generated projection
  functions;
- copy variable-length strings, bytes, and arrays only into the final projected
  archive bytes.

Local rkyv evidence:

- rkyv 0.8.16 exposes `Archive`, `Serialize`, and `ArchivedVec` APIs.
- `ArchivedVec::serialize_from_iter` accepts an `ExactSizeIterator + Clone`
  over borrowed values implementing `Serialize`.
- `ArchivedVec::serialize_from_slice` is available for contiguous slices.

The benchmark Bars proto must preserve the old MBT field numbers,
dictionaries, projection declarations, nested metadata shape, ignored UTC
fields, key fields, presence bits, and projection groups. It must remove only
non-MBT cache/db annotations that this repository does not own.

## Unknowns

- Whether `ArchivedVec::serialize_from_iter` internal resolver storage is below
  the old owned-row projection cost for all row counts.
- Whether a fully manual archive writer is necessary if the borrowed rkyv writer
  does not meet parity.

These are benchmark questions, not reasons to keep the current owned-row
projection path.

## Risks

- Incorrect generated `Archive`/`Serialize` implementations could produce
  bytes that validate but carry wrong field semantics.
- Presence-bit remapping can regress if source and projected fields are not
  bound by explicit mapping indices.
- Variable-width fields can reintroduce hidden allocations if emitted through
  owned `String`, `Vec<u8>`, or collected numeric vectors.
- Compile surface can grow for wide schemas if generated borrowed serializers
  duplicate too much code.

## Evidence Required Before Coding

- A spec that binds exact generated types, functions, forbidden code shapes,
  and benchmark lanes.
- Peer audit of that spec.
- An implementation plan with exact file edits and validation commands.

## Evidence Required Before Acceptance

- Generated-code negative checks proving projection functions do not emit:
  - `Vec::with_capacity(archived`
  - `rows.push(`
  - `encode_owned(rows`
  - `.to_string()`
  - `.to_vec()`
  - `.collect()`
- Correctness tests proving checked/trusted projection output validates as the
  projected schema and rejects as the source schema.
- Benchmark rows matching old Bars projection lane shape, with old-crate
  baseline values recorded next to new-crate values.
- Same-or-better archived projection performance versus old
  `mathilde_binary_project_*_archived` lanes using the Bars benchmark schema,
  or the implementation is not accepted.
